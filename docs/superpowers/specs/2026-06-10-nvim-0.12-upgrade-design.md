# Neovim 0.12 Upgrade Design

## Goal

Upgrade the nvim config to take advantage of Neovim 0.12 built-in completion, fix breaking changes, and remove ~10 plugins that are no longer needed.

## Scope

Option B: replace nvim-cmp and its companion plugins with native 0.12 completion. Keep lazy.nvim, treesitter setup, LSP server configs, and all keybindings intact.

---

## Section 1: Completion Migration

### Plugins removed (10 total)

| Plugin | Reason |
|---|---|
| `hrsh7th/nvim-cmp` | replaced by native completion |
| `hrsh7th/cmp-nvim-lsp` | native completion handles LSP capabilities |
| `hrsh7th/cmp-buffer` | dropped |
| `hrsh7th/cmp-path` | dropped |
| `hrsh7th/cmp-cmdline` | dropped (native cmdline completion works by default) |
| `saadparwaiz1/cmp_luasnip` | dropped (snippets unused) |
| `L3MON4D3/LuaSnip` | dropped (snippets unused) |
| `rafamadriz/friendly-snippets` | dropped (snippets unused) |
| `windwp/nvim-autopairs` | replaced by `mini.pairs` (mini.nvim already installed) |
| `onsails/lspkind.nvim` | dropped (completion kind icons not required) |

### Replacement

`vim.lsp.completion.enable(bufnr, { autotrigger = true })` called in an `LspAttach` autocmd in `lua/plugins/completion.lua`.

Options set globally:

```lua
vim.o.completeopt = 'menu,menuone,noinsert,fuzzy'
```

`noinsert` preserves the current "no auto-select" behaviour (equivalent to nvim-cmp's `select = false` on `<CR>`). `fuzzy` is new in 0.12 and improves match ranking.

Autopairs via `mini.pairs` (already available from the installed `mini.nvim`):

```lua
require('mini.pairs').setup()
```

### Keybinding mapping

All existing bindings are preserved:

| Binding | Behaviour |
|---|---|
| `<C-y>` | confirm selected item (identical to pum default) |
| `<C-e>` | abort completion (identical to pum default) |
| `<CR>` | confirm only if item explicitly selected; otherwise insert newline |
| `<Tab>` | `pumvisible() ? '<C-n>' : '<Tab>'` |
| `<S-Tab>` | `pumvisible() ? '<C-p>' : '<S-Tab>'` |
| `<C-b>` | scroll docs popup up (native pum info window; may require explicit mapping) |
| `<C-f>` | scroll docs popup down (same caveat) |
| `<C-Space>` | manually trigger completion |

`<CR>` behaviour is achieved with `noinsert` in `completeopt` — the pum will not auto-insert the first match, so `<CR>` only confirms an explicitly highlighted item.

Lspkind completion-menu icons are dropped. Native completion shows text kind labels.

## Section 2: LSP Cleanups

### `lua/plugins/lsp.lua`

- Remove `cmp-nvim-lsp` from the `dependencies` list of `nvim-lspconfig`.
- Remove the `capabilities` block that calls `require('cmp_nvim_lsp').default_capabilities()`. `vim.lsp.completion.enable()` advertises completion capabilities automatically.
- The global `vim.lsp.config('*', { capabilities = capabilities })` call is removed along with the block.
- Update `fidget.nvim`: remove `tag = 'legacy'`. The current release config shape has changed from the legacy tag — verify the correct option keys against the current fidget.nvim README before updating the `config` block.
- Add an `LspAttach` autocmd to call `vim.lsp.completion.enable(args.buf, { autotrigger = true })`.

### `lua/plugin-manager.lua`

- Line 3: `vim.loop.fs_stat` → `vim.uv.fs_stat`. `vim.loop` is deprecated since 0.10 and will be removed.

### `lua/autocmds.lua`

- Remove the `CmpSourceCargo` autocmd group (calls `require("cmp").setup.buffer(...)` for `crates.nvim`, which is not installed — dead code).

### `lua/plugins/completion.lua`

- Replace the entire nvim-cmp plugin block (current lines 53–176) with the native completion setup described in Section 1.
- Keep the `github/copilot.vim` block unchanged.
- Keep the `olimorris/codecompanion.nvim` block; remove `"hrsh7th/nvim-cmp"` from its `dependencies` list.
